Lesson 2: Logical Agents and Propositional Reasoning

How an agent can represent what it knows with logical sentences and use those sentences to justify what it believes about its environment.

Autonomous software · Agents and environments · Knowledge bases · Propositional semantics · Models · Entailment · Model checking
01

What this lesson is about

This is the course’s first technical lecture. It looks at reasoning as a way to represent knowledge and make decisions. The focus is a logical agent: software that describes relevant facts about its world using symbols, stores those facts and rules in a knowledge base, and checks whether a possible conclusion follows from what it knows.

The lecture moves from a practical need—software operating amid changing devices and contexts—to a small, formal example. Propositional logic keeps the example simple enough that we can enumerate possible worlds and see exactly why a conclusion is justified.

Observe the environment→Represent facts and rules→Check a conclusion→Choose an action
02

Why autonomous software?

Modern computing systems combine many devices and software components. In a large, open distributed system, devices can move, change their properties, appear or disappear, and encounter contexts that were not fully known when the software was written. Components may also need to cooperate and provide services to one another.

A conventional program often has its knowledge encoded inside data structures and its behaviour encoded in the program logic. When the situation changes, adapting the system may require changing and redeploying code. The lecture’s motivation for agent-oriented software is to state a goal and let a system use the information it has to decide how to pursue it.

Separate knowledge from the reasoning mechanism

A useful design idea is to keep the domain knowledge—facts about a particular environment—separate from the inference mechanism that works with those facts. A general reasoning engine can then be reused with different knowledge bases. The system can also derive a fact that was not explicitly stored, provided it follows from the stored facts and rules.

This is the role of inference in the lecture: it lets the system extend or update the knowledge it can use, instead of merely executing a fixed list of steps. A real system still needs a way to acquire reliable information and to represent its domain correctly.

Core motivation: when the environment is dynamic and not completely known in advance, the software needs a representation of what it knows and a way to reason from that knowledge.

03

Agents, environments and task descriptions

An agent is a software system situated in an environment. It receives information through sensors and affects the environment through actions or actuators. The term is used in several fields, but here it is a programming abstraction: it lets us focus on the agent’s intelligent functionality while treating the basic interaction with the environment as part of the setup.

Environment→Sensors · percepts→Agent→Actions · actuators→Environment changes

To describe an agent problem in a way that supports reasoning, the lecture identifies four things to formalise:

Part of the taskWhat it describesLecture example
PerceptsThe information the agent receives from its sensors at a particular moment.A taxi driver perceives roads, traffic signs and pedestrians; a toy agent may receive a simple binary signal.
Actions / actuatorsThe choices the agent can make and the mechanisms by which those choices affect the environment.A vehicle changes speed or direction; the toy agent selects a move.
EnvironmentThe world in which the agent operates, including relevant objects, properties and relationships.Roads and traffic for a taxi; cells and possible hazards for the toy world.
Performance measureThe criterion used to judge whether the agent is doing well.For a taxi agent, safely delivering passengers is an example of a desired outcome.

In real applications, sensor readings and actions can be complex: a camera produces an image, for example, rather than one simple true-or-false value. The lecture deliberately begins with a simplified representation in which each selected feature can be represented by a binary variable. This makes the reasoning mechanics easier to study.

The transition model may be unknown

An action can change the environment. A transition model describes what happens when an action is performed in a particular situation. In an unfamiliar or changing environment, the agent may not know all valid actions or their outcomes in advance. It must gather information by interacting with the environment and use the resulting facts to assess what it can safely do.

04

What makes an agent logical?

A logical agent uses an explicitly represented body of knowledge and a formal inference process. In this lesson, the representation is propositional logic. The agent stores sentences in a knowledge base (KB), including observations and rules that describe the environment.

  1. Represent: use symbols to stand for meaningful facts or properties.
  2. Observe: add facts reported by the agent’s percepts.
  3. Reason: check what follows from the knowledge base.
  4. Act: use supported conclusions when deciding what to do next.

The logical agent does not treat every possible claim as known. If the knowledge base does not establish a fact, the agent may need to test a hypothesis against all worlds that remain consistent with what it knows. That distinction—between “not known to be true” and “known to be false”—matters in the example later in the lesson.

For this first model, the agent’s sensors and actions are simplified into binary variables. This is an introductory abstraction; it does not mean real-world perception or control is inherently binary.

05

Propositional logic: facts as true-or-false sentences

A proposition is a statement that can be assigned one of two truth values: true or false. A propositional symbol such as P12 can stand for a specific statement, for example, “there is poison in cell (1,2).” The symbol is only useful when its intended meaning is defined.

Propositions let us represent a simplified world as a set of variables. A particular assignment of truth values to those variables describes one possible state of that world. Logical connectives combine simpler propositions into more complex sentences.

P12 = “poison is in cell (1,2)”
¬P12 = “poison is not in cell (1,2)”

The lecturer calls the step of pairing a symbolic notation with its defined meaning the introduction of semantics. Without that mapping, symbols are just marks on a page; with it, a formula can say something about the environment.

What this representation can and cannot express

Propositional logic is a good fit for a small, finite environment where relevant statements can be enumerated. It can express whether a named fact holds and combine such facts using logical connectives. By itself, it does not express the internal structure of objects or general relationships with variables such as “every cell has a property.” Those richer descriptions require first-order logic, which is a later topic.

06

Worlds, models and meaning

The lecture uses world for a formally described version of the physical environment. A model is one possible assignment of truth values to the propositional variables used to describe that world. For example, if the possible poison locations are represented by three variables, each variable can be true or false. There are therefore 23 = 8 possible assignments before any rules or observations rule some out.

A sentence is true in some models and false in others. The set of models in which a sentence is true is its model set. This gives us a precise way to talk about what a sentence means and whether the knowledge base supports a conclusion.

TermMeaning in this lecture
Propositional variableA named true-or-false fact, such as P12.
ModelOne complete assignment of true or false to the variables in the description.
SatisfiesA model satisfies a sentence when evaluating the sentence under that assignment gives true.
Knowledge baseThe collection of sentences representing observed facts and rules available to the agent.

With n independent Boolean variables, there are 2n possible assignments. Some assignments may conflict with the rules or observations. The remaining assignments are the possible worlds consistent with the knowledge base.

07

Logical connectives

Connectives determine how the truth values of smaller sentences determine the truth of a larger sentence. The lecture later uses implication elimination and logical equivalences when checking entailment. These compact definitions are useful for reading and simplifying those formulas.

PQ¬PP ∧ QP ∨ QP → QP ↔ Q
FFTFFTT
FTTFTTF
TFFFTFF
TTFTTTT
  • Negation (¬P): true when P is false.
  • Conjunction (P ∧ Q): true only when both P and Q are true.
  • Disjunction (P ∨ Q): true when at least one of P or Q is true (including when both are true).
  • Implication (P → Q): false only when P is true and Q is false. It can be rewritten as ¬P ∨ Q.
  • Biconditional (P ↔ Q): true when P and Q have the same truth value; it expresses that each implies the other.

Reading implication carefully: “if P, then Q” rules out the case where P happens but Q does not. When P is false, the implication is true under the truth-table definition. It does not by itself claim that P is true.

08

Entailment and logical equivalence

Entailment asks whether a knowledge base logically supports a sentence. We write KB ⊨ α (“KB entails alpha”) when every model that makes all sentences in KB true also makes α true.

KB ⊨ α exactly when Models(KB) ⊆ Models(α)

In plain language: take every possible world that agrees with the knowledge base. If the proposed conclusion is true in all of them, the conclusion follows. If even one compatible model makes the conclusion false, the knowledge base does not entail it.

Entailment is a relation between sentences. It is stronger than saying that a conclusion seems likely, or that one example world happens to make it true. A conclusion must hold across all models consistent with the premises.

Worked example: going to a party and having money

Let P mean “I go to the party” and M mean “I have money.” The lecture compares P ∧ M with P ↔ M.

PMP ∧ MP ↔ M
FFFT
FTFF
TFFF
TTTT
  • P ∧ M ⊨ P ↔ M is true: the only model where both P and M are true makes them equivalent.
  • P ↔ M ⊨ P ∧ M is false: the model P = false and M = false makes the biconditional true while the conjunction is false.

That second row is a counterexample to the proposed entailment. One counterexample is enough to show that entailment does not hold.

Logical equivalence

Two sentences are logically equivalent when they have the same truth value in every model. The truth tables let us compare them row by row. For example, P → Q and ¬P ∨ Q are equivalent because they are true and false in exactly the same cases.

Logical equivalence can be used to replace a formula with a simpler or more convenient one without changing its meaning. In the lecture, implication is rewritten using disjunction and negation so the resulting expression can be checked systematically.

Useful formula from the handwritten notes: a biconditional expands into two implications:

P ↔ M ≡ (P → M) ∧ (M → P)
≡ (¬P ∨ M) ∧ (¬M ∨ P)

This is the same truth-functional meaning: P and M must have matching truth values.

09

The poison-world example

The lecture applies the definitions to a small grid environment. A poison can be located in one of a few candidate cells. The agent does not initially know which placement is the real one, so each possible placement is represented by a model. As observations arrive, some models are ruled out.

Representing observations

Use a proposition such as P12 for “poison is in cell (1,2).” A sensor at the agent’s current cell reports a smell when poison is in a neighbouring cell. In a simplified two-neighbour case, the rule can be written:

S11 ↔ (P12 ∨ P21)

Here, S11 means “the sensor at (1,1) reports a smell.” The biconditional records both directions of the assumed relationship: the smell is present when a neighbouring cell contains poison, and under this toy-world rule, it is present only in that case. The actual lecture’s grid supplies the relevant neighbouring cells; the formula above names a compact illustrative instance.

At the start, the agent can add directly observed facts to its knowledge base. For example, it knows its starting cell is not poisoned. It also records the sensor reading and the rule connecting that reading to nearby poison locations.

From a sensor reading to a conclusion

Suppose the sensor reports no smell. The knowledge base contains ¬S11 and the rule above. In every model where that rule and observation are true, both listed neighbouring poison propositions must be false. So ¬P12 and ¬P21 are supported by the knowledge base.

The important step is not simply to guess that the next cell is safe. The agent states the proposed fact as a hypothesis and checks whether it is true in every model compatible with its rules and observations. When it is, the fact may be added to the knowledge base and used in later reasoning.

Evidence versus absence of evidence: if the agent has not observed a cell and its rules do not determine what is there, the cell’s status remains unknown. The agent should not mark it safe merely because “poison” is not currently listed as a fact. It needs entailment from the knowledge base.

10

Model checking: testing whether a conclusion follows

The lecture introduces model checking as a way to perform inference in propositional logic. It works by considering the models that satisfy the knowledge base and checking whether the proposed hypothesis is also true in each one.

  1. List the propositional variables used to describe the small world.
  2. Enumerate their possible true/false assignments, which are the candidate models.
  3. Keep the models in which every sentence in the knowledge base is true.
  4. Check the hypothesis in each remaining model.
  5. If the hypothesis is true in all of them, KB entails it; if it is false in any one, KB does not entail it.

For the poison example, the hypothesis is that there is no poison in a particular cell. The agent checks every model that satisfies its observation and sensor rules. If there is no compatible model containing poison in that cell, the knowledge base entails that the cell is poison-free.

Why the number of models matters

Evaluating a formula in one already specified model is straightforward: substitute the truth values and calculate the result. Entailment is more demanding because it asks about every model consistent with the knowledge base. With n Boolean variables, the full set contains 2n assignments. That number doubles each time another variable is added, so exhaustive enumeration grows exponentially.

Model checking is therefore a clear and valid method for small examples, but larger problems need more efficient ways to search or establish satisfiability. The lecturer names satisfiability checking as a family of methods to study next; the detailed SAT methods are outside the main development of this lesson.

Entailment as a satisfiability question

The handwritten notes connect model checking with a proof-by-contradiction test. To test whether KB ⊨ α, ask whether there is a model in which the knowledge base is true while the proposed conclusion is false. That is exactly the satisfiability question for KB ∧ ¬α.

KB ⊨ α exactly when KB ∧ ¬α is unsatisfiable

If KB ∧ ¬α is satisfiable, its satisfying model is a counterexample: it agrees with the knowledge base but makes α false. If it is unsatisfiable, no counterexample exists, so every model of KB must satisfy α. This is the logical bridge from exhaustive model checking to the SAT-solving methods introduced next.

11

Key ideas and quiz focus

  • An agent receives percepts from an environment and changes it through actions.
  • A useful task description identifies percepts, actions, the environment and a performance measure.
  • A logical agent stores observations and rules in a knowledge base, then applies inference.
  • Propositions are true-or-false sentences whose symbols need a defined meaning.
  • A model is one truth-value assignment; different models represent different possible worlds.
  • KB ⊨ α means every model that satisfies KB also satisfies α.
  • To disprove entailment, find one counterexample model where KB is true but α is false.
  • Logical equivalence means two formulas agree in every model.
  • Model checking tests a hypothesis across all models that satisfy the knowledge base.

The lecturer says to expect quiz exercises on simplifying logical formulas using equivalences and on understanding entailment. The party example is a useful pattern to practise: build the truth table, identify the rows where the premise is true, then check the conclusion in those rows.
